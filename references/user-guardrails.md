# 用户侧护栏：防用户卡住

M6 审的是 **AI 有没有假执行**。但管道还有另一类失败：

> **AI 每一步都做对了，用户卡住了。**

用户不补信息、不回应论证、看不懂清单、选不出来——管道停在原地，而且**它不认为自己是失败的**，因为检查项全都通过了。M6 看不见这类失败（它只查 AI 的产物），所以单独一层。

---

## 总原则

1. **任何等用户的地方，必须有出口。** 卡点是岔路口不是终点。用户不回应时要有默认动作，不许原地空转。
2. **最多追 2 次。** 第 3 次还问不出来，说明问法有问题或用户真的不知道——换策略，不要继续问。
3. **问就是选择题。** 开放题是把思考的活推回给用户，而用户正是因为想不明白才来找你。
4. **卡住时降级，不升级。** 用户在一层卡住，给他更小的问题，不是更大的。

---

## 逐节点护栏

| 节点 | 用户会怎么卡 | 救援动作 |
|------|------------|---------|
| **M0 入口** | 不知道 Gateway 能干什么、不敢开口 | 开场白一句话说清：`这个得拆开做，我先理一下你的目的和现状。` 不介绍架构 |
| **M1 解析** | 需求太模糊，提取不出目的 | 最多追 2 次，**必须是选择题**；仍模糊 → 按"目的未成型"进 M2，让对标数据帮他把目的照出来；用户说"我不知道" → 停止追问，不进死循环 |
| **M2 卡点①** | 不补 / 答不上来 / 越补越偏 | **见下节，这是最容易死的地方** |
| **M3 卡点②** | 看完论证沉默、只说"我再想想" | 给一个**最小验证动作**让他做（不是让他继续想）；明确告诉他"想不清楚可以先做这一步，做完就有答案了" |
| **M4 量化** | 面对十几条清单不知道从哪开始 | **永远突出第一步**，完整清单折叠在后。不展示所有动作的全部细节 |
| **M5 卡点③** | 一直补上下文但不确认 | 已确认规则：补充信息不算确认。此时**明确问一句**"这些是补充，还是确认可以按这个跑？" |
| **执行中** | 做完一个动作不知道下一步 | **面包屑**（见下） |

---

## 🚦 卡点① 的三种卡法与出口（核心）

卡点① 是管道里唯一一个「AI 停下来等用户输入」且**没有默认动作**的地方。用户不回应，管道就死在这里。三种卡法分开处理：

### 卡法 1：不回应 / 说"你看着定"

**不许阻塞。** 用 M2 检索来的同行基准填默认值，在 `state.md` 标注：

```
时间边界：6 周（默认值，来自同行基准，用户未确认）
```

继续进 M3。在卡点③ 的摘要里提一句"有 N 个维度用的是默认值，跑之前最好确认一下"。

### 卡法 2：答不上来（"我也不知道"）

**给假设让他确认或纠正**，不要继续开放地问：

> ❌ 那你的成功标准是什么？
> ✅ 我猜是「跑通一次完整流程」，对吗？不对的话，是 A 收到第一笔钱，还是 B 先验证有没有人需要？

用户答不上来往往不是没想法，是被问法卡住了。给选项他就能认出来哪个不对。

### 卡法 3：反复补但补不到点上（第 3 次仍缺）

**第 3 次是硬上限。** 到这一步不再追问，改为：

```
我把现在的状况摊开：

确定的：{列出，3-5 条}
不确定的：{列出，1-3 条}

按确定的往下走，不确定的我先当假设处理——
{假设内容，写进 state.md}
```

然后进 M3，并在卡点③ 摘要里明确标出哪些结论依赖假设。

### 卡法 3 的一个例外：缺的是「目的清晰度」

**目的清晰度是根。** 其他维度缺了可以带假设往下走，目的清晰度缺了不行——后面 M3 的论证、M4 的排序全部建立在目的上，目的错了后面全是错。

缺其他关键项（现状/约束/成功标准/时间边界）→ 可以给默认值或假设，进 M3。
**缺目的清晰度且 3 次问不出来 → 不进 M3。** 改为：

1. 用 M3 的「问题有效性」思路，帮他把问题本身拆清楚（他问的常常不是他真正的问题）
2. 或者终止管道，明说：**"你想要的这个东西我现在问不出来，先做这一步你就有答案了"** + 给一个能帮他看清目的的最小动作

**宁可终止，不要带病往下跑。** 带一个错误的目的跑完 M3-M5，产出的提示词会非常完整、非常可执行、且完全指向错误的地方。

## 面包屑

每次把控制权交给用户（等他补充、等他确认、等他执行完回来），**必须留一句面包屑**：

```
完成后告诉我，我接着做 {下一步}。或者直接说 {关键词} 回到这里。
```

没有面包屑的交接 = 用户做完不知道怎么回来 = 管道事实性中断。这在导航仪路径（指路给某个 Skill）和执行路径（按提示词跑）里都是硬要求。

---

## 三条通用救援动作

任何节点卡住，从这三个里挑一个，不要发明新动作：

| 动作 | 什么时候用 | 怎么说 |
|------|-----------|--------|
| **列确定/不确定** | 信息不全但有一部分能用 | "确定的我先按这些走，不确定的留着后面校准" |
| **给默认值** | 用户授权你决定，或明显不关心这个维度 | "我按同行基准定的 X，你觉得不对随时改" |
| **降级** | 用户在当前层答不出来 | 把问题换成一个他能答的更小的问题 |

---

## 与 M6 的分工

| | M6 审计层 | 本护栏层 |
|---|---|---|
| 防谁出错 | AI | 用户 |
| 查什么 | 步骤真做了吗、有没有造假 | 用户有没有卡住、卡住有没有出口 |
| 失败表现 | 产物是空壳、谎报检索 | 管道停住不动、反复追问同一件事 |
| 判定依据 | 文件、行号、检索记录 | 轮次计数、用户回应模式 |

**两层都要有。** 只防 AI 不防用户，管道会在"每一步都正确"的状态下静静死掉。
