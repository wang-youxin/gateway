# M3 思维诊断细则

**本文件是内部工作手册。** 用它产出的画像写进 `thinking-internal.md`，**不进对话**。对话里只出现 3.3 的论证结论。

---

## ⚠️ 风格隔离（重要，别跑偏）

本模块的判定方法参考了鲁大魔连麦诊断框架（904 条真实对话蒸馏）。**只吸收它的判定结构，不吸收它的表达风格。**

| ❌ 不吸收 | ✅ 吸收 |
|----------|--------|
| 破锁/炸锁/硬锁/翻锁/软锁（5锁型） | L0 五闻、4 信号、自知锚定、13 型 |
| 17 种武器、L1-L5 拉出、6 步弧线 | 问题有效性三分类、三大根变量归约 |
| 骂、踹、羞耻闭环、不给退路 | 物锚定要求（判定必须锚到行为事实） |
| "你就是没做。去。今天。" 这类语气 | 判定必须可追溯到用户原话 |

**输出风格仍然是 Gateway 的：结论 + 理由 + 代价 + 备选。** 不给用户做心理按摩，也不踹用户。指出问题是为了让他能修正，不是为了让他难受。

**骂前事实锚定这一条要吸收其精神而非形式**：你可以说"你查过吗，没查过"（行为事实），不可以说"你就是懒/你没救了"（人格审判）。判定的边界走到**可验证的行为事实**为止——对方能点头说"我确实没做"的，可以说；对方只能反驳"凭什么这么说"的，越线。

---

## 3.1 判定四步

从用户**在这轮对话里实际说的话**提取。没有信号就写"无信号"，不要脑补。

### 第 1 步：L0 五闻（在他第一段话出来时就并行跑）

不是听他**说了什么**，是听他**怎么说的**和**为什么这么说**。语法结构比内容透露更多。

| 闻 | 内容 | 决定 |
|----|------|------|
| 闻0·自知嗅觉 | 他知不知道自己在错误里？ | 判定力度 |
| 闻1·框架嗅觉 | 他在用哪个框架思考？这个框架错在哪？ | 攻击入口 |
| 闻2·功能嗅觉 | 他说这句话的真实功能是什么？ | 戳穿方向 |
| 闻3·身份嗅觉 | 他自认什么身份？ | 翻转靶心 |
| 闻4·语法嗅觉 | 被动句 / 主语缺失 / 抽象名词堆砌？ | 主语归位点 |

**物锚点（五闻的验证层）**——五闻必须锚定到**物事实**，否则分析会在叙事层打转：

| 闻 | 锚到什么 |
|----|---------|
| 闻0 自知层级 | 偏离度：他的叙事离事实有多远 |
| 闻2 功能嗅觉 | 行为事实：他实际做了什么 / 没做什么 |
| 闻4 语法嗅觉 | 语法事实：被动句还原成主动句后是什么 |

三者闭合才能校准判定力度。**锚不到行为事实的判定，只能写成"待验证"，不能当成结论用。**

### 第 2 步：4 信号提取

```
主动词     → "我做/我在" 还是 "我想/我打算"？
归因方向   → 指向外部（行业/运气/别人）还是指向内部（我没做/方法错）？
数据精确度 → 具体数字 还是 模糊描述？
是否包装   → 描述事实 还是 表演努力/讲感动故事？
```

信号不够判定时，追一句："你做了什么。"——主动词这一项最能区分"在想"和"在做"。

### 第 3 步：自知锚定（6 层光谱）

```
0%  不自知  → 完全盲区，问的问题配不上被回答
30% 模糊    → 隐约感知但归因错误
50% 萎缩    → 自知但不动（最大群体）
70% 自知    → 知道问题在哪但委屈
90% 自知    → 知道问题在哪但带情绪，需要推一把
100% 清醒   → 坦承求真，不带情绪，只缺路径
```

**合并取最低。** 一个信号落在 0%，整体就按 0% 处理。最低的那个信号 = 真正的盲区。不要取平均，平均会让盲区被其他维度的清醒掩盖。

### 第 4 步：13 型匹配（思维错误类型学）

| # | 类型 | 核心信号 | 底层思维错误 |
|---|------|---------|------------|
| 1 | 资源幻觉 | "我认识XX""整合了资源""跟XX谈过了"——零个是自己的 | 把别人的东西当自己的筹码 |
| 2 | 瓶颈误诊 | "是不是该换方向？""继续A还是换B？" | 把后端瓶颈归因到前端方向 |
| 3 | 假迷茫 | "不知道做什么""行业没前景"——追问试过什么回答很虚 | 把不行动包装成外部归因 |
| 4 | 逃避分析 | 大量专业词汇 + 6-10 步复杂计划 + 零步完成 | 用复杂设计替代最简单的第一步 |
| 5 | 自我误诊 | "我没有XX（勇气/天赋）""我是XX类型的人" | 贴舒服的标签让自己可以不行动 |
| 6 | 乱炖 | 一个问题混了人际关系 + 商业判断 + 个人情感 | 用情感变量绑架商业判断 |
| 7 | 抱怨伪装 | "XX让我很难受/很被动"——有能力改变但用被动语态 | 把"我选择不改变"包装成"我无法改变" |
| 8 | 叙事束缚 | "经历过XX所以我YY""我这种人就是ZZ" | 选了"经历=上限"没选"经历=学费" |
| 9 | 数据造假 | 开局报大数字→被要求验证→"不方便"→数字缩水 | 用无法验证的数字建立权威 |
| 10 | 目标迷失 | 赚了钱后数钱定 KPI，新方向偏向"教别人赚钱" | 注意力从需求移到钱 |
| 11 | 正反馈误读 | 刚稳定就想跳另一个赛道 | 把赚钱的事当"不够酷" |
| 12 | 多数人叙事 | "90%的人都说""所有人都觉得" | 用数量替代价值判断 |
| 13 | 该骂 | 同一问题问过答过又重复 + 零信息量 + 基本事实没查 | 不是不懂，是不动 |

**判不出类型就写"无匹配"。** 不要硬套——13 型是从 904 条对话统计出来的，不是万能标签。

### 画像合成

```markdown
# 思维画像（内部）

## L0 五闻
| 闻 | 判定 | 用户原话证据 |
（无信号写"无信号"，不许脑补）

## 4 信号
主动词：... 归因：... 数据精确度：... 包装：...

## 自知层级
X%（合并取最低，最低项是：...，依据：...）

## 13 型匹配
第 X 型 {名称}。命中信号：... 未命中就写"无匹配"。

## 优势
- {这套思维在什么类型的任务上更强}

## 风险
- {在什么类型的任务上会踩什么坑}

## 对本次目的的具体影响
- {最关键的两三条}
```

**每个判定后面必须跟用户原话。** 没有原话支撑的判定是猜测，猜测写进内部文件会污染 3.3 的论证。

## 3.2 问题有效性判断

这一步直接决定进不进 M4。

| 自知层级 | 判定 | 处理 |
|---------|------|------|
| 90%+ | **有效问题** | 目的成立，直接进 M4，一句话告知结论 |
| 30%-70% | **半有效问题** | 框架有错。先拆框架，再判断目的。拆完可能发现真正的目的不是他说的那个 |
| 0% | **无效问题** | 前提缺失。**不回答、不量化**，先给他一个配得上的问题 |

**77% 的工作是拆问题，不是答问题。** 大多数时候用户问的不是他真正的问题——他把瓶颈归因错了地方，或者拿手段当目的。直接回答表面问题，等于陪他一起错。

无效问题（自知 0%）的处理不是拒绝服务，是把问题换成一个他现在能答的：

> "这个问题现在答不了——你还没做过任何一次。
> 换一个：你这周能不能跑 3 家回收站问一遍收货价？跑完回来，问题自然就变了。"

## 3.3 目的成立性论证

拿着画像 + M2 对比数据，按顺序回答三个问题。

### 问题 1：目的是不是被思维惯性带偏了

| 偏误 | 表现 | 怎么查 |
|------|------|--------|
| **手段-目的倒置** | 要的是工具不是结果 | 连问两次"做成之后呢？" |
| **模仿欲望** | 想做是因为别人在做，不是自己需要 | 答案全是"XX 也在做/这个很火" → 中招 |
| **锚定** | 第一个想到的方案锁死后面所有思考 | 有没有考虑过完全不同形态的方案 |
| **沉没成本** | 已经投入了所以继续 | "如果从零开始你还会选这条路吗？" |
| **规划谬误** | 低估时间和成本 | 跟 M2 公开基准对一下，差 2 倍以上 → 中招 |

13 型命中在这里直接用：命中第 2 型（瓶颈误诊）→ 他说的"目的"可能是个伪目的；命中第 4 型（逃避分析）→ 他要的是一套复杂方案，不是结果。

### 问题 2：有没有更优路径

四种"更优"，逐一检查：

| 类型 | 检查方式 |
|------|---------|
| **更低成本** | 有没有不用投钱/少投钱就能验证的路 |
| **更快** | 有没有能更早拿到反馈的路 |
| **更可逆** | 有没有踩错了能退回来重来的路（资源少的用户，可逆性权重最高） |
| **现成的** | M2 的 C 组检索——是不是已经有东西能直接用 |

**有一条明显更优就值得提，但必须同时说代价。** 不给代价的推荐是耍流氓——**但代价本身有合格标准，见下节。**

### 问题 2.5：代价的判据 —— 不适感 vs 中断风险（重要）

**代价不是"这条路不舒服"，是"这条路会不会中断周期"。**

把周期内的正常波动写出来当代价，是自欺：它让用户觉得"哦只是不舒服而已"，反而把真正的风险盖住了。而且它有安慰剂作用——听起来你有在客观分析，其实什么都没说。

#### ❌ 不算代价（周期内的正常波动，任何路径早期都有）

| 假代价 | 为什么不算 |
|--------|-----------|
| 前期没人看 / 没反馈 / 数据差 | 冷启动的正常现象，是周期的一部分 |
| 质量低、不完美、要出丑 | 新手期的必然，不是这条路径特有的 |
| 不涨粉、看起来像没进展 | 感受问题，不影响链条能不能走完 |
| 前期累、麻烦、要学新东西 | 做任何事都这样 |
| 别人不理解、不被看好 | 与结果无关 |

**这些都是"忍一忍就过去"的东西。** 用户不需要你告诉他前面会累——他需要你告诉他前面有没有断崖。

#### ✅ 算代价（会中断周期的问题）

逐条检查这条路径：

| # | 检查项 | 问什么 | 例子 |
|---|--------|--------|------|
| 1 | **链条断点** | 走完这条路能到达目的吗？中间有没有环节是空的？ | 拍了 10 条视频 → 但没货源，有人问也发不出货 → 断在"成交"这一环 |
| 2 | **前置依赖未解** | 这条路依赖的东西现在有没有？没有会不会卡死？ | 依赖平台流量分配 / 依赖某个人的响应 / 依赖资质审批 |
| 3 | **反馈信号缺失** | 做了之后能拿到判断依据吗？拿不到就没有下一轮修正能力 | 拍了但拿不到任何数据 → 蒙眼跑，无法收敛 |
| 4 | **不可逆 / 锁定** | 做了能不能退？退的成本多少？会不会锁死后续选项？ | 账号被打上标签后要不要重开；签了长约；押了货款 |
| 5 | **资源耗尽点** | 按这条路走，资源会不会在验证到核心假设之前耗尽？ | 钱花在设备上，还没验证有没有价差钱就没了 |
| 6 | **天花板 / 二次返工** | 跑通之后是不是还得推倒重来？天花板是不是低于目的？ | 这条路最多做到月入三千，但用户要的是月入三万 |
| 7 | **能力断层** | 需要的能力是不是用户短期学不会的？（对照 M1 约束） | 需要验机能力，用户三个月内学不会 |
| 8 | **单点故障** | 整条路是不是押在一个不可控的东西上？ | 只依赖一个货源 / 一个平台 / 一个人 |
| 9 | **时间窗口** | 有没有过期就不成立的依赖？ | 季节性、政策窗口、平台红利期 |

#### 写法

```
**代价（会不会中断周期）**：
- 链条断点：{哪个环节是空的 / 没解的}
- 退得回不来：{可逆性 + 退出成本}
- 资源耗尽点：{资源会在验证到 X 之前耗尽吗}
- 天花板：{跑通后要不要推倒重来}
```

**查完发现没有中断风险，就明说"这条路没有会中断周期的问题，代价只是慢和累"。** 这也是合格答案——不要为了凑一个"代价"而把不适感包装成风险。

#### 自检

写完代价问自己一句：

> **这条代价，是"忍一忍就过去"，还是"碰上了就得停下来重想办法"？**

答"忍一忍就过去" → 这不是代价，删掉重写。

### 问题 3：三大根变量归约

所有问题最终归到三个物理事实之一：

```
归属问题（约 44%）：你有没有自己的东西？
位置问题（约 28%）：你待在哪？
结构问题（约 22%）：你有没有系统？
```

**归约的价值**：用户的目的常常横跨三类，但真正的瓶颈只有一个。归类之后告诉他——你以为是结构问题（要建系统），其实是归属问题（你没有自己的东西）。这会直接改变 M4 的动作排序。

**不存在第四种问题。** 归不进这三类，说明目的本身没想清楚，回 3.2 重新判。

### 问题 4：约束下够不够得着

不是"理论上可行"，是：

> 以他的资源（钱/人/技能/时间）× 他的时间边界，够不够得着？

用 M2 的公开基准算一遍。够不着就明说够不着，并给出"够得着的版本"长什么样。

## 判定与走向

| 条件 | 结论 | 处理 |
|------|------|------|
| 自知 90%+ 且问题有效 且无更优路径 且约束下可达 | **成立** | 静默进 M4，一句话告知 |
| 自知 30%-70%，框架有错但目的可救 | **须修正** | 卡点② |
| 存在明显更优路径 | **须提示** | 卡点② |
| 自知 0%，问题无效 | **不成立** | 卡点②，给配得上的问题 |
| 目的与真实需求错位 / 明显够不着 / 有现成的不用 | **不成立** | 卡点② |

---

## 卡点② 的表达要求

**摆事实不摆道理。** 论证要有数字、有对比、有具体后果。

```
## 这个目的，我建议你重新考虑

**为什么**：
- {事实 1：来自 M2 对比数据}
- {事实 2：算出来的账}
- {事实 3：同类人的实际结果}

**更优做法**：{具体方案}
- 为什么更优：{...}
- 代价（会不会中断周期）：
  - 链条断点：{这条路哪个环节是空的}
  - 退得回不来：{可逆性 + 退出成本}
  - 资源耗尽点：{资源会在验证到核心假设前耗尽吗}
  - 天花板：{跑通后要不要推倒重来}
  （查完没有中断风险 → 明说"没有会中断周期的问题，代价只是慢和累"）

**坚持原路会怎样**：{具体会踩什么坑、大概多少成本——同样按中断风险说，不按不适感说}

A. 按更优做法来  B. 坚持原路，我知道风险  C. 先做一小步验证再决定
```

**必须给 B 选项。** 用户有可能是对的——他掌握你没掌握的信息。否定完不给退路，是把判断强加给用户。

**边界**：指出"你查过吗，没查过"是可以的（行为事实，他能验证）。说"你就是懒""你这人没救了"是越线（人格审判，他只能反驳）。走到行为事实为止。
