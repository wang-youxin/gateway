# M6 审计层细则

审计层存在的唯一理由：**AI 会假装完成了。**

不是恶意，是结构性的。当被要求"严格按 5 步走"时，模型最容易做的事是——写出一份完美的 5 步执行记录，而每一步的实际动作都没发生。产出看起来比真做的还规范，因为它是照着规范写出来的。

所以这份文件的所有检查项，都必须指向**可验证的外部证据**，不指向"执行者说它做了"。

---

## 通用证据标准

每一条检查项的结果只有四种：

| 结果 | 含义 | 什么时候用 |
|------|------|-----------|
| ✅ PASS | 有具体证据，证据可复核 | 能拿出文件路径/行号/检索记录/来源链接 |
| ⚠️ COND | 做了一半，或证据弱 | 不影响主干，记下来放行 |
| ❌ FAIL | 没做，或造假 | 退回重做 |
| ⬜ 未验证 | **审计者查不出证据** | 按 FAIL 处理 |

**⬜ 未验证 = FAIL。** 这条不能松。审计 Agent 查不出证据时，默认判定是"没做"，不是"大概做了"。松了这一条，整个审计层就废了——因为所有造假项最终都会落到"未验证"这个筐里。

### 什么算证据

| ✅ 算 | ❌ 不算 |
|------|--------|
| `state.md` 第 42 行记录了 M2 检索结果 | "M2 已完成" |
| 3 次 WebSearch 调用的关键词与返回条数 | "已检索公开数据" |
| 数字后标注来源：`毛利率 15-25%（来源：xxx 行业报告）` | 光秃秃的数字 |
| `agent-prompt.md` 存在，2.1KB，含九个章节 | "提示词已生成" |
| 卡点① 有用户原话回复记录在 `state.md` | "已与用户确认" |

## 反模拟红名单

这九种是实际会发生的假执行。审计时逐条对照。

### 1. 谎报检索

**长什么样**：M2 输出里写着"同行做法是…""公开数据显示…"，内容看着专业，其实全是模型记忆编的。

**怎么抓**：
- 对话/执行记录里有没有 WebSearch 或 WebFetch 的实际调用
- 输出里的每个外部事实，能不能追到一次检索
- 检索次数 < 2 组，但输出里塞满了外部数据 → 可疑
- 输出里有"未搜到"的诚实标注 → 反而可信

### 2. 编数据

**长什么样**：`行业均值 ¥X` `转化率 3%` `同行平均 6 周`，数字精确到像真的，但无处可查。

**怎么抓**：
- 每个数字后面有没有来源标注
- 来源是不是具体到可查（行业报告名/年份 > "据行业数据"）
- 拿其中一个数字反向搜一下，看对不对得上

### 3. 空文件 / 幽灵文件

**长什么样**：说"已生成 agent-prompt.md"，文件要么不存在，要么是几行的占位符。

**怎么抓**：
- 逐个路径做存在性检查
- 检查文件大小（正常产出的量级）
- 检查关键章节标题是否都在（M5 是九个章节，缺一个就是没写完）
- 检查内容里有没有占位符残留：`{...}` `TODO` `待补充` `XXX`

### 4. 代办卡点

**长什么样**：该停下来问用户的地方，执行者自己替用户决定了，然后写"已确认"。

**怎么抓**：
- 三个卡点在 `state.md` 里有没有**用户原话**记录
- 没有用户回复但流程继续了 → FAIL
- 用默认值填的维度有没有标"(默认值，来自同行基准)"

### 5. 跳模块

**长什么样**：M1 直接到 M4，中间的 M2/M3 在 `state.md` 里是空标题。

**怎么抓**：
- `state.md` 里五个模块的状态段落是不是都有实质内容
- 模块写入顺序对不对
- 后一模块的输入能不能在前一模块的输出里找到（M4 的动作，应该能追溯到 M1 的目的）

### 6. 模板化填充

**长什么样**：产出结构完整、格式漂亮，但内容全是通用表述，换任何一个需求都适用。

**怎么抓**：
- 有没有引用**用户原话**（没引用用户的话，说明没真读需求）
- 有没有具体名词：地名、金额、产品名、时间
- 把用户的需求换成另一件事，这段输出还成立吗？成立就是模板化

### 7. 泄露内部文件

**长什么样**：`thinking-internal.md` 里的思维画像原文进了对话。

**怎么抓**：
- 对话里有没有出现"你的思维是…""你倾向于外归因"这类表述
- M3 给用户的输出里，有没有出现六维信号表的术语

### 8. 自我合理化

**长什么样**：审计发现问题时，执行者用"这个维度对本次需求不重要""简化处理了"来解释。

**怎么抓**：
- 任何"不重要所以跳过"的说法，都要能说清为什么不重要
- 流程里的模块是用户定的，执行者无权判定哪个不重要
- 真觉得不适用，应该上报用户，不是自己砍掉

### 9. 不适感冒充代价 ★ 最容易发生

**长什么样**：M3 卡点② 里"代价"一栏写的是——"前 10 条大概率没人看""质量会比较低""基本不涨粉""看起来像没进展""前期会累"。

**为什么这是假执行**：这些是**周期内的正常波动**，任何路径早期都有。把它写进"代价"，看起来是在客观分析，实际什么都没说——**更糟的是它有安慰剂效应**：用户读到"只是没人看而已"，会以为风险可控，而真正的断崖（比如链条断在成交环节、钱花完了还没验证到核心假设）被盖住了。

**怎么抓**：
- 逐条问：这条代价是「忍一忍就过去」还是「碰上了得停下来重想办法」？前者一律判不合格
- 检查有没有覆盖四类中断风险：链条断点 / 退不回得来 / 资源耗尽点 / 天花板
- 出现"没人看、没反馈、数据差、质量低、不涨粉、要出丑、会累、别人不看好"等表述 → 直接判 FAIL
- 确实没有中断风险的情况，必须明说"没有会中断周期的问题，代价只是慢和累"，不能拿不适感凑数

## 五道闸门检查清单

### 闸门 1 — M1 出口（L1 自检）

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 1.1 | 目的是结果态 | 不是"做个 App"，是"App 达成后的那个状态" |
| 1.2 | 现状/约束/特殊点都填了 | 填不出写"未知"，不留空 |
| 1.3 | 引用了用户原话 | 至少 1 处，证明真读了需求 |
| 1.4 | 没有给方案 | M1 输出里不出现"你应该""建议" |
| 1.5 | 写入 `state.md` | 文件存在且有内容 |

### 闸门 2 — M2 出口（L2 独立审计）

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 2.1 | 真的检索了 | 有 ≥2 组检索记录，关键词与返回条数可查 |
| 2.2 | 数据有出处 | 每个外部数字带来源标注 |
| 2.3 | 搜不到的诚实标注 | 没搜到的维度标了"公开数据稀缺"，没拿记忆充数 |
| 2.4 | 对比表非空 | 至少 3 个维度有对比 |
| 2.5 | 差距标了性质 | 资源差/认知差/阶段差，不是笼统"有差距" |
| 2.6 | 完备性判定有据 | 7 个维度逐项判，判定结果跟表对得上 |
| 2.7 | 卡点① 合规 | 触发了就必须真的等用户；用默认值的标了"(默认值)" |

### 闸门 3 — M3 出口（L2 独立审计）

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 3.1 | `thinking-internal.md` 存在且有实质内容 | 判定四步都有结果，不是空模板 |
| 3.2 | **L0 五闻判了** | 五个闻都有判定，无信号的写"无信号"，没有留空或脑补 |
| 3.3 | **物锚定** | 五闻锚到了行为事实；锚不到的标了"待验证"，没被当结论用 |
| 3.4 | **4 信号齐全** | 主动词/归因/数据精确度/包装，四项都有 |
| 3.5 | **自知锚定合并取最低** | 给了层级且说明了最低项是哪一项；取了平均 = FAIL |
| 3.6 | 13 型有匹配或无匹配声明 | 命中要写命中信号；没命中写"无匹配"，不许硬套 |
| 3.7 | **原话证据** | 每个判定后面引了用户原话；无原话的判定是猜测 = FAIL |
| 3.8 | **问题有效性判了** | 自知 90%+ / 30-70% / 0% 三档给了结论；0% 时没直接进 M4 |
| 3.9 | 优缺点都列了 | 只列优点或只列缺点 = 没做 |
| 3.10 | 三大根变量归约 | 归到归属/位置/结构其中之一；归不进说明目的没想清，应回 3.2 |
| 3.11 | 判定跟论证一致 | 结论"成立"但论证里列了明显更优路径 = 逻辑断裂 |
| 3.12 | **不外泄** | 对话输出里没有画像术语和原文 |
| 3.13 | **风格没跑偏** | 没有出现踹/骂/人格审判；判定走到行为事实为止 |
| 3.14 | 卡点② 给了 B 选项 | 不成立时必须给"坚持原路"退路 |
| 3.15 | **代价是中断风险不是不适感** | 覆盖 链条断点/退不回得来/资源耗尽点/天花板；出现"没人看/质量低/不涨粉/会累" → FAIL；确实无中断风险要明说 |

### 闸门 4 — M4 出口（L1 自检）

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 4.1 | 动词开头 | 是"列出 10 家回收站价格"不是"价格体系" |
| 4.2 | 验收可判真假 | "表里能算出单件毛利"，不是"价格合理" |
| 4.3 | **验证三层齐全** | 每条有 自动/人工/结果；只给验收不给验证方式 = FAIL |
| 4.4 | **没有标题含「和/&/with」的动作** | 有就是没拆干净 |
| 4.5 | **没有水平切片** | 每条都是完整路径，不是"调研市场/调研竞品/调研价格"这种并列切片 |
| 4.6 | 粒度合规 | 2-4h，>8h 已拆，<30min 已合并 |
| 4.7 | **高风险动作已前置** | 最容易翻车的排在前面，没攒到最后 |
| 4.8 | 依赖无环 | 没有 A 依赖 B、B 依赖 A |
| 4.9 | **每 2-3 个动作有 Checkpoint** | 8 条以上无检查点 = FAIL |
| 4.10 | 动作能追溯到目的 | 每个动作能对上 M1 的目的，没有凭空多出来的 |
| 4.11 | 自适应模式对 | 完整模式做了路径反推/形态定义/落地反推；简化模式没做多余的 |
| 4.12 | >8 条分了组 | 且标了第一轮、突出了第一步 |

### 闸门 5 — M5 出口（L2 独立审计）

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 5.1 | 文件真的存在 | 路径存在，大小合理，非占位符 |
| 5.2 | **做过 Loop 适配判断** | 五类结论给了明确一个；默认就写 loop 没判断 = FAIL |
| 5.3 | **选了主模式且说了为什么不是其他** | 五选一，有排除理由 |
| 5.4 | **产物档位是最轻够用的** | 说明了为什么不选更重的 |
| 5.5 | **决策依赖 Gate 过了** | 关键判断列了依赖证据；缺证据的标了"未校准"，没假装校准过 |
| 5.6 | 十章节齐全 | 目标非目标/工具池/角色/调度循环/交接/闸门/断路器/终止条件/禁止动作/最小卡/动作清单 |
| 5.7 | Skill 池真实 | 每个 Skill 名能在 `index.json` 里查到，路径存在，写了用途和触发条件 |
| 5.8 | 终止条件可判真假 | 有文件/数字/闸门结果，不是"做好了" |

| 5.10 | 角色有"不能做"列 | 没写越界边界的角色 = 会崩 |
| 5.11 | loop 有最大轮次**且有推导过程** | 由复杂度/反馈成本/风险/回滚性推导；用场景默认值 = FAIL |
| 5.12 | 交接靠文件 | 写了产物目录和命名规则 |
| 5.13 | 质量闸门可判真假 | 每条闸门能判对错 |
| 5.14 | **断路器四类齐全** | 轮次 / 连续无改善 / 越界 / 成本权限 |
| 5.15 | **禁止动作清单 + 不可逆动作留人工确认** | merge/发布/生产配置/权限/支付/数据删除/商业上架 |
| 5.16 | **动作清单没缩水** | 条数 ≥ M4 输出；M4 给 6 条这里变 2 条泛化任务 = FAIL |
| 5.17 | 冷启动测试 | 假装不知道上下文，照着能跑完吗 |

## L2 独立审计的派发方式

### 派发提示词模板

```
你是本次任务的独立审计员。你不参与执行，只判定执行者有没有真的按流程做完。

## 你要审的对象
- 产物目录：{绝对路径}
- 被审模块：M{N} {模块名}
- 流程规范：{references/module-{N}-*.md 的路径}

## 你的权限
- 可以读：产物目录下的所有文件、流程规范文件
- 禁止修改：state.md、thinking-internal.md、agent-prompt.md 以及任何被审对象
- 你只能输出判定，不能帮执行者补做。发现问题写进报告，让执行者自己改。

## 判定规则
1. 每个检查项必须给出证据（文件路径、行号、检索记录、来源）
2. 查不出证据的检查项，判为「未验证」，按 FAIL 处理，不许判 PASS
3. 不要采信"已完成""已检查"这类自述，只认可复核的外部证据
4. 特别注意这九种假执行：谎报检索、编数据、空文件、代办卡点、跳模块、模板化填充、泄露内部文件、自我合理化、**不适感冒充代价**（写"没人看/质量低/不涨粉"这类周期波动当代价 = FAIL）

## 输出格式
| 检查项 | 结果(PASS/COND/FAIL/未验证) | 证据 |
（逐项填，证据栏写具体的东西）

**总判定**：PASS / CONDITIONAL / FAIL
**FAIL 项与重做要求**：{具体到补哪一步}
```

### 三条硬约束

1. **不许帮着补做。** 审计员发现 M2 没真检索，正确做法是判 FAIL 让执行者去重搜，不是自己顺手搜一下填上。审计员一旦开始补做，它就变成了执行者，独立性没了。
2. **不许采信自述。** 执行者说"已联网检索"，审计员要的是检索记录，不是这句话。
3. **不许批发 PASS。** 全项 PASS 且证据栏都是"已完成"式的空话，说明审计员在走过场——这时的正确处置是换一个审计员重审，不是采信结果。

### 审计员自己的元审计

在 `audit-log.md` 里对每次 L2 加一行元判定：

```
**审计质量自检**：本次 N 个检查项中，有证据的 X 项，无证据的 Y 项。
无证据项 > 0 → 本次审计无效，重派。
```

## 处置流程

```
闸门判定
   │
   ├── PASS ──→ 写 audit-log.md → 进下一模块
   │
   ├── CONDITIONAL ──→ 记录瑕疵 → 写 audit-log.md → 进下一模块
   │                    （卡点③ 的摘要里提一句这些瑕疵）
   │
   └── FAIL ──→ 告诉用户卡在哪（不要静默重做）
                  │
                  ├── 第 1 次 → 退回模块重做 → 重审
                  ├── 第 2 次 → 再退回 → 重审
                  └── 第 3 次仍 FAIL → 上报用户，停止管道，说明卡在哪一步、为什么过不去
```

**FAIL 必须让用户知道。** 静默重做三次然后告诉用户"跑通了"，跟一开始造假没区别——用户失去的是对过程的知情权。

上报时说清三件事：卡在哪道闸门、哪项检查不过、需要用户提供什么才能过得去。

---

## 代价（说在前面）

审计层不是白拿的：

- **时间**：每道 L2 闸门多花 20-40 秒，一次完整管道多 1-2 分钟
- **啰嗦**：FAIL 时要打断用户说明情况，不能闷头重做
- **误伤**：严格的证据标准会把一些"其实做了但没留痕"的工作判成 FAIL。留痕本身就是成本，但这个成本是值得付的——不留痕的工作，事后无法复核，跟没做差别不大

想关掉：`/gateway` 时说"跳过审计"，或指定"只过 L1"。但默认开。
